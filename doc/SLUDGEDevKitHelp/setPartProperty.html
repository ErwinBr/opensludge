setPartProperty

Syntax:

setPartProperty (character, part, property, value);

Purpose:

Sets a property of a part of character straight from your script, and keeps it there, whatever the character's clips are doing.

Clips are great for movements you know in advance, but some things depend on the game: a head that turns to follow the mouse, say, or an arm that holds up whatever the player just picked up. For those, set the property here. It wins over every clip on every layer, and stays set until you call clearPartProperty.

These are the properties, with the same units as in clipKey:

  • PART_X and PART_Y: the position, in pixels.
  • PART_ROTATION: the angle, in degrees, clockwise.
  • PART_SCALE, PART_SCALE_X and PART_SCALE_Y: the size, in percent.
  • PART_DEPTH: the depth among the other parts (see setPartDepth).
  • PART_VISIBLE and PART_FLIP: TRUE or FALSE.
  • PART_MODULATE_R, PART_MODULATE_G, PART_MODULATE_B and PART_MODULATE_A, and the same four of PART_SELF_MODULATE: the colour, in percent from 0 to 200. A colour outside that range stops the game with an error.

The value is always a whole number. Sprites can't be set this way: play a clip with clipSprite on a layer instead (see playClip).

Watch the spelling of the part's name! A name that isn't a part of the character doesn't give an error: the property is set, but nothing on the screen changes, and you're left wondering why.

Return value:

Returns TRUE if there is such a character, otherwise FALSE.

Example:

objectType ego ("Ego") {
}

sub nod () {
   setPartProperty (ego, "head", PART_ROTATION, 15);   # Tilt the head forward...
   pause (10);
   clearPartProperty (ego, "head", PART_ROTATION);     # ...and let the clips move it again
}

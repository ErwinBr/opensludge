Projects

A SLUDGE project (a .slp file) holds the settings of a game and the list of its scripts. In the Dev Kit, you make a project with File > New > Project, and open one with File > Open or by double-clicking it. One project is open at a time, in the Project panel:

The list at the top shows the files which make up the project. They should be text files with the extension ".SLU" (for scripts), ".SLD" (for constants) or ".TRA" (for translation files). The order of the files is not important (unless your script attempts to set the start value of a global variable to another which has not yet been created). Prototyping functions and externing variables from other files is not required.

Add files with Add..., or by dropping them on the Project panel, and remove the selected ones with Remove, which doesn't delete them from your computer: they just won't be included the next time the project is compiled. Drag a file to move it in the list. You can select several files with Ctrl-click (Command-click on macOS) and Shift-click. Double-click a file to open it: a script in your text editor, and a translation in the Dev Kit.

The list at the bottom contains all the resources which are used by the selected scripts: the pictures, sounds, floors and other files that they name. Double-click one to open it.

The settings of the project are in the Inspector: see Project Settings.

Compiling and running

Compile the game with Compile in the Project menu, the Project panel or the Build panel. The compiler saves the project first, and shows its progress, errors and warnings in the Build panel. Double-click an error to open its script at its line. When the game has compiled, Run Game plays it in the SLUDGE engine.

Projects from other systems

A project builds on every system when its scripts are UTF-8 text and name their files in the case that the files have on disk. Windows and macOS forgive another case, but Linux doesn't. Projects made with the old Windows versions of SLUDGE often have neither. Project > Check Files finds these problems, and fixes the ones that you choose: it converts scripts to UTF-8, keeping the old file with .orig after its name, and writes the names of files as they are on disk. The compiler finds files in any case on every system, and warns when the case differs.

clipKey

Syntax:

clipKey (clip, part, property, tick, value);
clipKey (clip, part, property, tick, value, easing);

Purpose:

Sets the property of part to value at tick in clip, from where it moves smoothly towards the next key.

This is how a Composite Character moves its parts: you say where the arm is at tick 0, where it is at tick 12, and SLUDGE works out everything in between. tick can be anything from 0 to the length of the clip. A key outside the clip stops the game with an error.

These are the properties you can key. The value is always a whole number:

  • PART_X and PART_Y: the position of the part, in pixels, from its parent.
  • PART_ROTATION: the angle, in degrees, clockwise.
  • PART_SCALE: the size, in percent, the same in width and height. 100 is full size, 50 is half, 200 is double.
  • PART_SCALE_X and PART_SCALE_Y: the width or the height only, in percent, along the part's own axes. In a clip that has both, these win over PART_SCALE.
  • PART_DEPTH: which parts this one is drawn in front of (see setPartDepth), for example to bring an arm round in front of the body.
  • PART_VISIBLE: TRUE or FALSE. FALSE hides the part, and the parts hanging from it.
  • PART_FLIP: TRUE mirrors the part, and the parts hanging from it.
  • PART_MODULATE_R, PART_MODULATE_G, PART_MODULATE_B and PART_MODULATE_A: the red, green, blue and alpha (opacity) of the part and the parts hanging from it, in percent from 0 to 200. 100 leaves the sprite as it is, less darkens, tints or fades it, and more brightens it. A part's colour is multiplied by the colours of the parts it hangs from. A colour outside 0 to 200 stops the game with an error.
  • PART_SELF_MODULATE_R, PART_SELF_MODULATE_G, PART_SELF_MODULATE_B and PART_SELF_MODULATE_A: the same, but for this part only: the parts hanging from it keep their own colours.

The easing says how the property gets from this key to the next one:

  • EASE_LINEAR: at a steady speed. This is what you get if you leave the easing out.
  • EASE_INOUT: slowly at the start, faster in the middle, and slowly again at the end, which looks much more natural for swings and bobs.
  • EASE_STEP: not at all. The property holds its value until the next key, and then jumps.

PART_DEPTH, PART_VISIBLE and PART_FLIP always step, whatever easing you give them, because there's nothing in between half visible and visible. The last key is where a movement ends, so its easing does nothing. Before the first key, the property has the value of the first key, and after the last key, the value of the last one.

Add all the keys before you use the clip: once a character plays it, it can't change any more. In the Animation Editor, the easing of a key is its Towards the next key in the Inspector, and the colour of the key on the timeline.

Return value:

No return value.

Example:

sub breathe () {
   var c = newClip (48, TRUE);
   clipKey (c, "torso", PART_Y, 0, -250, EASE_INOUT);    # Start at -250...
   clipKey (c, "torso", PART_Y, 24, -262, EASE_INOUT);   # ...ease up to -262...
   clipKey (c, "torso", PART_Y, 48, -250);               # ...and back down again
   return c;
}
